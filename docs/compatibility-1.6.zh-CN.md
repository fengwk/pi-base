# Pi 1.6 兼容性检查

## 已适配：TUI 渲染结果只读

Pi 1.6.0 将 `Component.render()` 的返回值声明为 `readonly string[]`。`Container` 在内容不变时还会复用缓存数组。旧版 pi-base 有 4 处类型检查错误，其中子 Agent 面板会把等待提示直接写入 `Container` 的输出。回归测试在未修复的 Pi 1.6.0 环境中确认了这次写入。

流式工具预览和子 Agent overlay 现在沿用宿主的返回类型，不复制完整渲染结果。子 Agent 面板在 transcript 为空时用单独的数组显示等待提示，不修改 transcript 缓存。开发依赖与 lockfile 同步到 `1.6.0`，peer 版本要求仍为 `^1.2.0`。

## `find` 相对路径 glob 迁移

`find` 不再给相对路径 glob 隐式加 `**/`。`src/*.ts` 只匹配搜索根下的 `src`，要跨层须写 `**/src/*.ts`。文件名模式如 `*.ts` 保持递归；前导 `./` 忽略、不会限制深度。`find.pattern` 的说明和工具示例随实现一起更新。详见 [`find` 的匹配范围与迁移示例](tools/find.zh-CN.md)。

这是有意改变搜索范围，不是对 `fd` 或 `rg` 全部选项做对齐。保持大小写、忽略规则、绝对模式、上限、取消和输出契约；`grep` 不变。

## 保留 `read` 行为

`read` 对不支持图片的模型仍返回文本提示，引导使用 `image-understanding` skill。原生 `read` 在 1.6 改为保存附件并按请求过滤，该变化不适用于 pi-base 的文本回退分支；切到视觉模型后需要重新读取此前以文本回退的图片。

## Pi 1.6.1

开发依赖和 lockfile 升至 `1.6.1`，宿主 peer 仍为 `^1.2.0`。pi-base 不调用新版删除的缓存提示设置接口，无需迁移。

权限弹窗向 1.6.1 报告 `blockedKind: "permission"`，旧宿主仍可使用原有选择和取消流程。Bash 完整输出写入失败时，折叠预览也会显示原因；若 pi-base 需要再次截断，发给模型的提示仍会保留原因。

## 验证

- Pi `1.6.1` / Node.js `22.23.5` / Linux：类型检查通过，90 个文件、1,195 个测试全部通过。另用 Pi `1.2.0` 验证生产源码类型检查及权限、Bash 渲染和输出截断相关的 50 项定向测试。
- Pi `1.6.0` / Node.js `24.14.0` / Linux：类型检查、覆盖率门槛和依赖审计通过；88 个文件、1,163 个测试全部通过。Windows 相对 glob 分支用模拟进程验证，未在 Windows 实机上跑全量。
- 本机 Pi `1.6.0`：在隔离配置下用 RPC 核对 Agent 的默认模型和显式 CLI 模型、thinking 优先级。另用仅含合成文件的测试目录检查三个模型：DeepSeek V4.1 Flash、MiniMax M3 和 GPT-6.2 Sol 对根下与跨模块搜索都选对了 glob，6 个调用返回预期路径。模型请求不包含历史会话或实际仓库内容。
- Pi `1.2.0` 隔离环境：生产源码通过类型检查，6 个相关文件的 70 个定向测试通过。1.2 不是全量开发测试基线：已有的 `tests/edit-argument-errors.test.ts` 使用 1.2 不提供的宿主解析接口。
